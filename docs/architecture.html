Architecture overview

Factory Inventory Management System

A demo full-stack dashboard. A Vue 3 single-page app talks to a FastAPI service over REST. The service serves JSON fixtures held in memory. There is no database and no persistence. Every request filters the same in-memory lists.

System architecture

The system has three tiers. Shared state such as filters, locale and the mock user lives in module-level composables, not in a store library.

Data flow: changing a filter

This is the main interaction. Four global filters scope the Dashboard, Orders, Inventory and other views.

  1. User picks a filter in FilterBarTime Period, Warehouse, Category or Order Status.
  2. Shared refs update in useFiltersModule-level refs, so every view sees the same values.
  3. View watcher calls getCurrentFilters()Maps the UI names to API names (location becomes warehouse, period becomes month).
  4. api.js builds the query stringLeaves out any value equal to 'all'.
  5. FastAPI filters the in-memory listsapply_filters matches warehouse, category and status. filter_by_month matches a month string or a quarter.
  6. Pydantic validates the responseThe response model shapes the JSON.
  7. The view stores it in refs; computed properties derive the restKPIs, charts and tables re-render reactively.
UI filterAPI paramApplies to
Time Periodmonthorders, dashboard. Accepts 2025-MM or Q1-2025…
Warehousewarehouseinventory, orders, dashboard

Order Statusstatusorders, dashboard

Inventory has no time dimension, so it ignores month. Demand, backlog, spending and reports endpoints take no filters. Views that use them filter on the client or not at all.

Data model

The JSON files are the source of truth, and each one has a matching Pydantic model in main.py. If you change a file's shape, update its model too.

Relationships: backlog.order_id points to an order, backlog.item_sku and demand.item_sku point to an inventory SKU, and purchase_order.backlog_item_id points to a backlog item. The API derives has_purchase_order on each backlog response. Warehouses: San Francisco, London, Tokyo. Categories: circuit boards, sensors, actuators, controllers, power supplies.

Observations

These are worth knowing before you change anything.

Frontend calls endpoints the backend doesn't haveThe /api/tasks and /api/purchase-orders calls in api.js get a 404. The tasks UI in App.vue and the purchase-order flow therefore can't work end to end yet.
Backlog view is not routedviews/Backlog.vue exists, but main.js has no route for it. Backlog data appears only on the Dashboard and in BacklogDetailModal.
Quarters are hard-coded to 2025QUARTER_MAP and the quarterly report only recognise 2025 dates. Orders from any other year are skipped.
Two hard-coded API base URLsapi.js and Reports.vue each hard-code http://localhost:8001. There is no Vite proxy and no env variable.
Nothing persistsAll state is in memory. Even once write endpoints exist, their changes would be lost when the server restarts.
Month filter matches by substringfilter_by_month checks month in order_date. That works for ISO dates, but the match is loose.
